# ADR-0017: PDF generation with OpenPDF
- **Status:** Accepted (2026-11-20, owner) - issue `[E6-4]`
- **Context:** Release 1 prints prescriptions (`[E6-5]`), invoices and payment receipts (api-design.md sections 9 and 10). The documents are small, structured and tabular (header, key-value block, item table, footer), generated on demand inside the monolith. They must be produced server side without a browser, a separate service or native binaries (operational simplicity, CLAUDE.md section 1), with a licence that allows commercial closed-source use.
- **Decision:** Use **OpenPDF** (`com.github.librepdf:openpdf`, version **2.4.0**, pinned in `backend/gradle/libs.versions.toml`; licence **LGPL-2.1 or MPL-2.0**, dual, our choice) behind a thin helper `com.hms.shared.pdf.PdfDocumentBuilder` (header with organization name and address, headings, key-value block, table, diagonal watermark, footer with page numbers). Modules build documents only through that helper and pass already-resolved business data; internal UUIDs, PHI beyond what the document needs, and secrets are never printed. Built-in Helvetica fonts for Latin text; embedding an Indic font is a later change if the owner needs local-language names. Tests extract text with OpenPDF's `PdfTextExtractor` and assert lines, never bytes (plan R7).
- **Options rejected:**
  - *openhtmltopdf* (HTML/CSS to PDF; LGPL-3.0): nicer layout authoring, but it adds an HTML templating step, pulls in PDFBox and more transitive dependencies, and CSS layout is more than these fixed forms need. Reconsider if documents become design-heavy.
  - *JasperReports* (LGPL-3.0): a full reporting engine with designer tooling, a large dependency tree and a second language (JRXML) to maintain; disproportionate for three small documents.
  - *Apache PDFBox directly* (Apache-2.0): free of copyleft, but low level (manual positioning and pagination of tables).
- **Consequences:** + one small dependency, no external process, deterministic output, easy text-level tests. + The LGPL/MPL licence permits use as an unmodified library in a proprietary product; if we ever modify OpenPDF itself we must publish those changes (legal review before redistribution of the product, per CLAUDE.md section 6). - Layout is code, not a template: changes to a document are Java changes. - Version 3.x of OpenPDF exists (3.0.5 at the time of writing, with a changed package name); the move to 3.x is a separate, deliberate upgrade. - Latin-only fonts until an embedded font is added.
