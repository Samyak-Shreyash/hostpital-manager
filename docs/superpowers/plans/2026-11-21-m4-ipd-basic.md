> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver M4 (wards/beds → admit with bed → transfer → room-day charges → interim/final IPD invoice → discharge → bed released), issues #65–#73 (`[E8-1]`…`[E8-9]`).

**Architecture:** Modular monolith (ADR-0001). `bedmanagement` owns Ward/Bed/BedAssignment and exposes `bedmanagement.api.BedAllocation`; `admission` owns Admission + DischargeSummary, calls `BedAllocation`, and implements billing's `billing.api.ChargeSource` port (admission → billing.api only; billing never imports admission). Invariants live in PostgreSQL (partial unique indexes, guard triggers) plus row locks, lock order bed → admission → invoice → `document_sequence` last. Frontend adds `frontend/src/features/ipd` following `features/appointments` and `features/billing`.

**Tech Stack:** Java 21, Spring Boot, JPA/JdbcTemplate (match neighbouring M3 repositories), Flyway, Testcontainers, React + TS + TanStack Query + RHF + Zod, Playwright. No new dependencies.

**Spec:** `docs/product/prd.md` §4.6 (IPD-1…IPD-9), BR-I1…I5, BR-B6, acceptance IPD-4; `docs/architecture/domain-model.md` (modules table, I1–I3, lifecycles, M1); `docs/api/api-design.md` §10, §11, §12; `docs/architecture/database-design.md` §6 (document_sequence), §20j; `docs/architecture/hld.md` §4 (ChargeSource); `docs/00-review-notes.md` Q1. ## Rulings made while planning (owner may overturn)

- R1 **Bed-day rule (BR-B6 option [A]) is implemented as the only rule**, pending pilot sign-off (Q1 stays open in `00-review-notes.md`; Task 4 adds a "needs sign-off" note). No per-org config switch now (YAGNI); the rule is one pure class so a second rule is a later strategy.
- R2 Rule [A] precisely: let `A` = admission date, `E` = end date (discharge date, or for a preview the `asOf` date), both in the org time zone. Charged dates are `A … E−1`; if that range is empty (same-day stay) charge `A` once. Date `D` is charged at the rate of the bed whose assignment covers the instant **00:00 of `D+1`** (midnight ending `D`); for the same-day case, the bed held at discharge/`asOf`. Rate = `ServicePriceLookup.priceAt(org, bed.dailyRateServiceId, start of D)`.
- R3 Bed rate: each bed has a required `daily_rate_service_id` → service catalog (api-design §10). One invoice line per (bed, consecutive date run, unit price): description `Room charges — <ward> <bedNo> (<from>–<to>)`, quantity = days.
- R4 Interim/final: `invoice.kind` `INTERIM|FINAL` (IPD only) and `invoice.room_charges_through date` (last charged date). A new IPD draft charges dates after the latest `room_charges_through` of the admission's live (not DISCARDED/CANCELLED) IPD invoices. At most one live FINAL per admission (partial unique index). FINAL requires admission status `DISCHARGE_INITIATED`; its `E` is the summary's planned discharge instant (R6).
- R5 `bedId` is required on `POST /admissions` (IPD-4 "allocate bed at admission").
- R6 Status flow: `PUT /discharge-summary` moves `ADMITTED → DISCHARGE_INITIATED` and stores `plannedDischargeAt`; `POST /discharge` → `DISCHARGED` in one transaction that releases the bed at `dischargedAt`, which must equal the FINAL invoice's charge end (else 422 — guarantees "final totals = preview"). `CANCELLED` only from `ADMITTED` with no live IPD invoice; it releases the bed.
- R7 Discharge summary becomes immutable at `DISCHARGED`: guard trigger with new SQLSTATE **`HM006`** (409 `IMMUTABLE_RECORD`, same mapping as HM001/HM005).

## Review Focus

1. Two admissions racing for the same free bed, and two racing for the same patient → exactly one wins (`BED_NOT_AVAILABLE` / `PATIENT_ALREADY_ADMITTED`), never a 500. (Tasks 2.)
2. Cross transfers A→B and B→A at the same time, plus a transfer into a bed someone is admitting into → no deadlock, invariants hold. (Task 3.)
3. Stays crossing midnight in IST while UTC date differs (e.g. admitted 2026-11-20T19:00Z = 00:30 IST on the 21st) → dates counted in the org time zone. (Task 4.)
4. Interim invoice then final invoice → no bed-day billed twice or skipped; interim discarded → its days are billed again by the next draft. (Task 5.)
5. Discharge failing after the bed release step (e.g. invoice not issued, version stale) → bed still assigned, admission unchanged. (Task 6.)
