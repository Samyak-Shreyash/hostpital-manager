# M3 OPD Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the M3 OPD slice (register → book → check-in → consult → Rx → invoice → pay → receipt) plus the open M2 prerequisite `[E2-3]`, issues #33 and #46–#64.

**Architecture:** Modular monolith (ADR-0001). New code lives in the existing `appointment`, `clinical`, `billing`, `payment` packages (`api`/`application`/`domain`/`infrastructure`/`web`) plus a new `patient/api` port for allergies. Invariants are enforced in PostgreSQL (exclusion constraints, partial unique indexes, `HM001` triggers) plus row locks. The frontend adds `appointments`, `consultation` and `billing` features following `frontend/src/features/patients`.

**Tech Stack:** Java 21, Spring Boot, JPA + JdbcTemplate (match neighbouring repositories), Flyway, Testcontainers, React + TS + TanStack Query + RHF + Zod, Playwright. New dependency: **OpenPDF** (owner-approved 2026-11-20).

**Spec:** `docs/api/api-design.md` §1, §7, §8, §9, §12; `docs/architecture/domain-model.md` §5–§7; `docs/architecture/database-design.md` §6, §7; `docs/product/prd.md` (APT-4/5, BIL-4/7/8/9/10, BR-A*, BR-C*, BR-B*); ADR-0010, 0011, 0012. The GitHub issues are thin; when an issue and these docs disagree, the docs win.

## Global Constraints

- Root `CLAUDE.md` §4–§7 bind every task (module boundaries, `@PreAuthorize` with permissions on every endpoint, org from the session only, other-org id → `404`, synthetic data only).
- Migrations: forward-only, next free number is **V24**. Each task below owns the version it names. Never edit V1–V23. Grant `hms_app` only the DML it needs (ADR-0015); append-only tables get **no** UPDATE/DELETE grant + `hms.reject_modification()` trigger.
- Money: `com.hms.shared.domain.Money`, `NUMERIC(14,2)`, JSON decimal **strings**, `HALF_UP` per line, total = Σ rounded lines (ADR-0012).
- Errors via `ProblemDetailsHandler`: `NotFoundException` (404), `ConflictException(code)` (409), `BusinessRuleException(code)` (422). Codes used: `INVALID_STATE_TRANSITION`, `SLOT_CONFLICT`, `ENCOUNTER_FINALIZED`, `INVOICE_IMMUTABLE`, `EXCEEDS_OUTSTANDING`, `CONCURRENT_MODIFICATION`, `VALIDATION_ERROR`, `BUSINESS_RULE_VIOLATION`.
- `version` optimistic locking on every mutable resource → `409 CONCURRENT_MODIFICATION`.
- `Idempotency-Key` header **required** on invoice issue, payment create, refund create.
- Audit in the same transaction: field **names** only; never clinical free text (reason, notes, diagnoses text, instructions).
- Number formats (api-design.md): invoice `2026-27/000031`, receipt `RCT-2026-27/000044`, credit note `CN-2026-27/000001`; FY Apr–Mar in the org time zone; allocate via `DocumentNumberAllocator.next(org, type, periodKey)` **last**, after other locks.
- Lock order: bed → admission → invoice.
- Each task ends with: `./gradlew.bat test integrationTest architectureTest` green (backend tasks) or `npm run lint && npm test && npm run build` (frontend tasks); `docs/api/api-design.md` "Implemented `[Ex-y]`" note + `database-design.md` section for each migration; conventional commit with the issue ID.

## Rulings made while planning (owner may overturn)

- R1 `[E2-3]` is already implemented (V9, `ServiceCatalogService`, `ServiceCatalogIT`) but the issue is open. Task 1 verifies it and the remaining AC "price change does not alter existing invoices" is pinned in Task 8 (items snapshot `unit_price`).
- R2 `[E5-1]` is implemented in `5d80733` incl. the 50-thread test; Task 1 only verifies.
- R3 Discount permission `invoice:discount` does not exist; Task 9 adds it (V30) and grants it to the templates holding `invoice:update`.
- R4 Refund approval threshold: config `hms.billing.refund-approval-threshold`, default `1000.00`. At or below → `RECORDED`; above → `PENDING_APPROVAL` until a **different** user with `refund:approve` approves.
- R5 Idempotency: one shared table `hms.idempotency_record (organization_id, key, endpoint, request_hash, response_status, response_body, created_at)`, PK `(organization_id, endpoint, key)`; same key + different body → `422 IDEMPOTENCY_KEY_REUSED`. Built in Task 10, reused in 11 and 12.
- R6 Queue tokens: counter row per `(org, doctor, date)` allocated by upsert (same pattern as `document_sequence`), plus unique `(organization_id, doctor_id, token_date, token_no)`.
- R7 PDF snapshot test = assert extracted text (OpenPDF `PdfTextExtractor`) contains the expected lines, not byte equality (PDFs embed timestamps).

## Review Focus

1. Cross-org ids on every new endpoint → 404 (add each endpoint to `OrganizationIsolationIT`).
2. Concurrent check-ins for one doctor/day → tokens 1..N, no gaps or duplicates.
3. Concurrent payments exceeding the outstanding amount → exactly one fails with `EXCEEDS_OUTSTANDING`.
4. Direct SQL UPDATE on finalized encounter children / issued invoice items / payments → `HM001`.
5. Rounding: lines like qty `3` × `33.33` with 18% tax and a discount produce totals equal to Σ rounded lines.
